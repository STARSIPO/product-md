# Product.md

B2B-маркетплейс оптовых продуктов для Молдовы. Соединяет фермеров, производителей и оптовых поставщиков с ресторанами, кафе, гостиницами, магазинами, кейтерингом, пекарнями и столовыми.

Две стороны рынка, и вторая — то, чем площадка отличается от доски объявлений:

1. **Поставщик публикует товар** — «Говядина охлаждённая, 95 MDL/кг, минимальный заказ 20 кг, доставка по Кишинёву».
2. **Покупатель публикует заявку** — «Нужно 20 кг охлаждённой говядины еженедельно с доставкой в Кишинёв», а поставщики присылают **закрытые коммерческие предложения**. Один поставщик никогда не видит цену, условия и вложения конкурента.

Product.md — информационная платформа. Она не является стороной сделки, не берёт комиссию и не принимает оплату за товары: покупатель и продавец рассчитываются напрямую.

## Технологии

| Слой | Выбор | Почему |
| --- | --- | --- |
| Фреймворк | Next.js 14, App Router | Серверный рендеринг публичных страниц для SEO, server actions вместо отдельного API-слоя |
| Язык | TypeScript, strict + `noUncheckedIndexedAccess` | Ошибка обращения к массиву — ошибка компиляции, а не `undefined` в проде |
| БД | PostgreSQL (прод) / SQLite (локально) | Одна схема, два движка — см. [`docs/DATABASE.md`](docs/DATABASE.md) |
| ORM | Prisma 5 | Типобезопасные запросы, защита от SQL-инъекций |
| Стили | Tailwind CSS + CSS-переменные | Вся палитра в токенах, тема меняется без правки компонентов |
| Формы | React Hook Form + Zod | Одна схема валидации на клиенте и на сервере |
| Хранилище | Локальный диск / S3-совместимое | Адаптер, переключается переменной окружения |
| Тесты | Vitest + Playwright | Unit, интеграционные и e2e |

## Быстрый старт

### Вариант A — без инфраструктуры (SQLite)

Самый быстрый путь: работает сразу после `git clone`, никаких контейнеров.

```bash
cd product-md
cp .env.example .env
```

Сгенерируйте секреты и подставьте их в `.env`:

```bash
node -e "console.log('APP_SECRET=' + require('crypto').randomBytes(48).toString('base64url'))"
```

```bash
node -e "console.log('PAYMENT_WEBHOOK_SECRET=' + require('crypto').randomBytes(24).toString('base64url'))"
```

```bash
node -e "console.log('CRON_SECRET=' + require('crypto').randomBytes(24).toString('base64url'))"
```

Дальше:

```bash
npm install
```

```bash
npm run db:push && npm run db:seed
```

```bash
npm run dev
```

Откройте <http://localhost:3000> — произойдёт редирект на `/ru` или `/ro` в зависимости от языка браузера.

### Вариант B — PostgreSQL в Docker (как в проде)

```bash
docker compose up -d db
```

В `.env` поменяйте две строки:

```dotenv
DATABASE_PROVIDER="postgresql"
DATABASE_URL="postgresql://productmd:productmd@localhost:5432/productmd?schema=public"
```

```bash
npm install && npm run db:push && npm run db:seed && npm run dev
```

> **Какой файл схемы править.** Единственный источник истины — `prisma/schema.prisma`, он написан под PostgreSQL. Prisma не принимает `env()` в поле `provider`, поэтому вариант для SQLite **генерируется автоматически** скриптом `scripts/prisma.mjs` в `prisma/schema.sqlite.prisma` (файл в `.gitignore`). Никогда не редактируйте сгенерированный файл — он перезаписывается при каждой команде `db:*`.

## Переменные окружения

Все значения проверяются Zod-схемой в [`src/env.ts`](src/env.ts) при старте: опечатка в имени переменной обрушит приложение с понятным сообщением, а не превратится в `undefined` внутри проверки прав.

| Переменная | Обяз. | По умолчанию | Назначение |
| --- | :---: | --- | --- |
| `DATABASE_PROVIDER` | да | `sqlite` | `sqlite` или `postgresql` |
| `DATABASE_URL` | да | `file:./dev.db` | Строка подключения |
| `APP_URL` | да | `http://localhost:3000` | Базовый адрес, используется в письмах и `sitemap.xml` |
| `APP_SECRET` | да | — | ≥32 символов. Подписывает сессии, шифрует TOTP-секреты. Смена разлогинивает всех |
| `SESSION_TTL_DAYS` | нет | `30` | Срок жизни сессии |
| `DEFAULT_LOCALE` | нет | `ru` | `ru` или `ro` |
| `STORAGE_DRIVER` | нет | `local` | `local` (папка `.storage`) или `s3` |
| `S3_*` | при `s3` | — | Endpoint, регион, бакеты, ключи |
| `MAIL_DRIVER` | нет | `console` | `console` (файлы в `.mail`) или `smtp` |
| `SMTP_*` | при `smtp` | — | Хост, порт, логин, пароль |
| `SMS_DRIVER` | нет | `mock` | `mock` (код в лог) или `http` |
| `PAYMENT_DRIVER` | нет | `mock` | `mock`, `maib`, `victoriabank`, `paynet`, `mia` |
| `PAYMENT_WEBHOOK_SECRET` | да | — | ≥16 символов. Подпись входящих вебхуков |
| `LISTING_DAILY_PRICE_BANI` | нет | `100` | Плата за объявление в день (100 бань = 1 MDL) |
| `SELLER_TRIAL_DAYS` | нет | `30` | Бесплатный период для новых поставщиков |
| `LOW_BALANCE_THRESHOLD_BANI` | нет | `1000` | Порог предупреждения о низком балансе |
| `CRON_SECRET` | да | — | ≥16 символов. Bearer-токен для `/api/cron/daily-billing` |
| `SENTRY_DSN` | нет | — | Пусто — ошибки идут в консоль |
| `LOG_LEVEL` | нет | `info` | `debug` / `info` / `warn` / `error` |

В production приложение **откажется стартовать**, если `APP_SECRET` или `CRON_SECRET` остались примерами из `.env.example`.

## Локальная разработка

Ни один внешний сервис не нужен — каждый заменён честной локальной реализацией, которая **не притворяется**, будто что-то отправила наружу.

| Что | Где искать |
| --- | --- |
| **Письма** | `MAIL_DRIVER=console` пишет каждое письмо в `.mail/<время>-<тема>.html`. Откройте файл в браузере — это настоящий просмотрщик, а не заглушка |
| **SMS-коды** | `SMS_DRIVER=mock` печатает код в лог сервера с префиксом `[sms:mock]` и явно пишет, что SMS **не отправлена**, потому что провайдер не подключён |
| **Загруженные файлы** | `STORAGE_DRIVER=local` кладёт их в `.storage/public` и `.storage/private`. Приватные отдаются только через `/api/files/...` по подписанной ссылке |
| **Платежи** | `PAYMENT_DRIVER=mock` проводит полный цикл «редирект → подтверждение → вебхук → зачисление на баланс» локально. Реальные деньги не двигаются |

Для реальных провайдеров (maib, victoriabank, paynet, mia) интерфейс `PaymentProvider` готов, но без ключей методы бросают понятную ошибку — фальшивой интеграции нет.

## Фоновые задачи

Ежедневное списание, снятие истёкших объявлений, закрытие заявок по дедлайну и очистка сессий выполняются одной задачей:

```bash
npm run cron:daily
```

В проде — по HTTP, раз в сутки:

```bash
curl -X POST https://product.md/api/cron/daily-billing -H "Authorization: Bearer $CRON_SECRET"
```

Задача **идемпотентна**: ключ идемпотентности записи в ledger имеет вид `listing-daily:<companyId>:<YYYY-MM-DD>` и защищён уникальным индексом. Повторный запуск в тот же день ничего не спишет — блокировки не нужны.

## Тестирование

```bash
npm test
```

```bash
npm run test:e2e
```

Покрыто главное:

- **`tests/integration/offer-privacy.test.ts`** — 12 тестов на то, что поставщик не видит предложение конкурента ни через один путь чтения. Это обязательное требование продукта, тест работает как детектор регрессии.
- **`tests/integration/billing.test.ts`** — идемпотентность ежедневного списания, частичная приостановка объявлений при нехватке средств, возврат после пополнения, сходимость баланса с ledger.
- **`tests/unit/`** — деньги (целые бани, никаких float), нормализация текста и опечаток, TOTP.

Интеграционные тесты работают на настоящей SQLite-базе `prisma/test.db`, которая создаётся и удаляется автоматически: проверяемые правила (уникальные индексы, внешние ключи) обеспечиваются самой БД, и мок проверял бы мнение мока, а не правило.

## Деплой

```bash
docker build -t product-md .
```

```bash
docker compose --profile app up -d
```

Перед первым запуском примените миграции:

```bash
docker compose exec app node scripts/prisma.mjs migrate deploy
```

Что важно знать:

- Образ многоступенчатый, рантайм содержит только `standalone`-вывод Next.js и запускается под непривилегированным пользователем.
- Health-check: `GET /api/health` — отдаёт состояние БД и **имена активных адаптеров**, чтобы было сразу видно, если в проде остался mock-платёжный драйвер. Секреты не отдаются.
- Обязательные переменные в проде: `APP_SECRET`, `PAYMENT_WEBHOOK_SECRET`, `CRON_SECRET`, `DATABASE_URL`, `APP_URL`. Значения из `.env.example` приложение не примет.
- При `STORAGE_DRIVER=local` каталог `.storage` нужно смонтировать на постоянный том, иначе документы пропадут при пересоздании контейнера. Для нескольких инстансов — только `s3`.
- **Бэкапы:** `pg_dump` базы + содержимое приватного бакета. Ledger — append-only, поэтому восстановление баланса на любой момент возможно из истории операций.
- **Откат:** миграции пишутся аддитивно (сначала добавить колонку, потом перестать использовать старую), чтобы предыдущая версия приложения продолжала работать на новой схеме.

## Диагностика проблем

| Симптом | Причина и решение |
| --- | --- |
| `Invalid environment configuration` при старте | В `.env` нет обязательной переменной. Сообщение называет её точно |
| `The schema at prisma/schema.prisma is not valid` | Изменили схему под SQLite-специфику. Схема должна оставаться в общем подмножестве обоих движков — см. `docs/DATABASE.md` |
| `Cannot find module for page: /[locale]/page` | Повреждённый кэш сборки, обычно после параллельного запуска второго дев-сервера. Остановите сервер, удалите `.next`, запустите заново |
| Категории в подсказках не обновились после правки в админке | Дерево категорий кэшируется в памяти на 5 минут. Админ-панель вызывает `invalidateCategoryIndex()`; при ручной правке БД перезапустите сервер |
| Письмо «не пришло» | При `MAIL_DRIVER=console` оно и не должно приходить — смотрите папку `.mail` |
| Не приходит SMS-код | При `SMS_DRIVER=mock` код выводится в лог сервера. Реальная отправка требует подключённого провайдера |
| Порт 3000 занят | `npm run dev -- -p 3200` |
